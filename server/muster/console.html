Overview

Mint a pairing code, then vouch for what presents itself.

Pairing code

Single use, and it expires in minutes. Type it into the device's Muster app - nothing on the device can scan a code, so this one is read off the screen and typed. A wiped phone does not need it: the provisioning QR carries its own.

Waiting to be vouched for

A typed request has the same fingerprint on the device's own screen, and comparing them is the whole security model. A scanned one does not: nobody is holding that phone, so there is no second copy to compare and each row says which it is.

Nothing is waiting.

Provisioning

Take a wiped device to Device Owner, with no cable.

Before you show it

  1. Factory reset the device and let it boot to the welcome screen. Stop there: going past it, and especially adding an account, means another reset.
  2. Tap the same spot on the welcome screen six times. That opens a scanner.
  3. Show the QR below and hold the device up to it.

A device provisioned now is bound to the key this agent is signed with. Device Owner cannot be replaced by a build signed with a different key - that takes another factory reset - so do this for a device that matters only once the signing ceremony is done. See docs/state-of-play.md.

What is this device for?

A role decides which policy the device gets. Leave it blank and it gets the kith's - the same as every other device. Name one and it also gets that role's, including app configuration the kith is never served.

Lowercase letters, digits and dashes. The role is fixed when the QR is made, because that is the only moment anything knows what this device will be - it has no identity yet.

Wi-Fi

The device needs a network before it can download the agent. Leave this closed and join one by hand in the setup wizard, or put the credentials in the QR and let it join on its own.

Put Wi-Fi credentials in the QR

The password goes into the QR in clear text, and the QR goes on this screen. Anyone who can see it, or photograph it over your shoulder, has your network password. It is not redacted, hashed or short-lived.

Policies

What a device is made to do once it is a member.

Policy is not authored here.

The restrictions in force, and which applications stay on the launcher, are files pushed to the device from the command line. The agent enforces them locally, so a device keeps its policy while Muster is unreachable - which is the same reason enrollment is the only part that needs the internet. Nothing about them travels through this page yet. See docs/policy.md for the files and how they are pushed.
